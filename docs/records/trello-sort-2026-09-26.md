# 歷史已交稿排序補正

日期：2026-09-26。依使用者提供的新網站與舊系統對照，延續已授權的排序修正與發布工作。

## 原因與修正

前一版僅按本站 `updatedAt` 排序，漏掉同批匯入及後續補金額／交稿日期，都會讓舊單的 `updatedAt` 集中於批次時間；歷史委託因此落到編號排序。新完成委託已有不同的本站更新時間，所以能排在前方。

第 25 版曾先處理「本站時間等於匯入時間」的情況，但正式瀏覽器比對仍失敗，才確認已交稿舊單後續補過帳務。最終 `contract.js` 從歷史逐筆核對，略過前後皆已交稿且只改金額／收益日期的時間，真正的進度、旗標、說明及其他內容更新仍保留。回溯至匯入且來源最後活動有效時，使用 `source.lastActivity`；不完整歷史停止回溯。判斷依實際差異，不硬寫特定批次編號。

公開及管理 API 提供同一個 `sortUpdatedAt`，分頁與前端補載共用排序；前端也可讀取舊版公開投影既有的來源時間。原本的 `updatedAt`、來源、修改歷史與收益日期均不改寫。

## 驗證

- 專案外的原始匯入資料中，47 筆歷史已交稿小動圖按修正後規則排列，逐筆與原看板 `cardPosition` 順序一致；公開投影與管理資料的排序一致。原始資料及真實名稱沒有加入測試或公開文件。
- 虛構的 35 筆案例涵蓋同批匯入後連續補金額／日期、公開／管理跨頁補載、未公開來源名稱、後續真正更新置頂、原始列不變，以及舊回應及無效來源時間相容。另驗證混合內容編輯、原生訂單及不完整歷史不被誤略過。
- 178 項離線測試全部通過；修改檔案語法檢查、正式網址建置、`npm run check` 與差異檢查通過。
- 以專案外保留的真實歷史快照補驗手動帳務編輯，原始 47 筆順序仍逐筆符合來源。
- 部署前分別備份 GAS 第 24／25 版，核對雲端未發布來源與正式版一致；後端只有 `Core.gs` 不同，manifest 與其他來源不變。

## 發布與界線

沿用既有 GAS deployment 與 main 驗證、production 快轉發布流程，先更新向後相容的 GAS 再發布前端。正式發布結果以 [Pages Actions](https://github.com/kt-productions/lanlan-pages/actions/workflows/pages.yml) 與 `release.json` 核對，完成後使用正式進度頁與使用者附圖比較。

本次不重新匯入、不改寫訂單、不發送通知，沒有持續同步舊系統。原始資料比對及離線測試不能代替正式頁面的最終驗收。
