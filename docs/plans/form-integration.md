# 委託服務後續規劃

本文件只保留尚未實作或尚待決策的能力，不作為已上線功能清單。現況與正式驗收依據見[現況對照](../development/current-state.md)，操作見[委託服務](../development/order-service.md)，欄位與相容性見[API 契約](../reference/order-api.md)。

## 已完成並移交維護的範圍

Sheets 收件、Telegram 管理登入、六階段公開看板、訂單編輯、封存、完整通知、私人附件與 Trello 一次性移轉，均已有現行文件。三天登入、管理金額、收益報表與作品管理也已有程式；各自的本機及正式驗收不能互相替代，發布狀態由現況對照及歷史紀錄說明。

不再在此重複維護 GAS 版號、Sheets 欄數、通知名單或收件開關，以免與操作文件及實際設定分歧。

## 尚未實作

| 項目 | 目前界線與待決策事項 |
| --- | --- |
| 委託附件自動清理 | 未完成預留及已收件附件仍保存；期限、通知、還原與清理授權須先確定。作品發布暫存清理是另一流程。 |
| 自動進度通知 | 現有通知只處理新收件與人工重試，不自動通知委託者階段變動。 |
| 委託者帳號或私人查詢 | 目前是公開工作看板，不提供委託者登入或私人查詢碼。 |
| 正式報價確認、付款及退款 | 管理員可記錄金額與收款日期，尚無委託者確認流程或金流串接；報表不代表系統已收款。 |
| 大量訂單與歷史容量 | 現有 Sheet、欄位容量及基礎限流適用小型工作室；擴充須保留歷史、相容性與可追溯性。 |
| 更完整的垃圾提交防護 | 現有配額及誘捕欄位之外的防護尚待需求，不因一般維護另加外部服務。 |

費率與確切範圍費用依[委託規格](../reference/commission.md)維護，不在方案文件推定營運規則。新增服務、資料清理、正式發布及真實通知仍依 AGENTS 與使用者授權。
