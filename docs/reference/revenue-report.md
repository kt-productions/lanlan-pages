# 收益報表

管理員登入後，由主導覽的「收益報表」直接開啟 `admin/?view=revenue`，透過「委託管理」回到看板。三個管理入口共用 Telegram 登入與身分驗證，未登入、登出、到期或後端確認權限失效時一起隱藏；報表 API 仍獨立檢查權限。直接開啟報表網址時，未登入只顯示登入區，完成登入或重新整理後仍呈現報表；OAuth 整頁回程僅接受固定的本站目的地。作品管理維持獨立頁面，不恢復「管理項目」切換列。依正式設定的 `details.quote` 計算，不採系統預估；金額與日期僅供管理員查看。前端維持原生 JavaScript 與 CSS，使用每月表格及按總計等比例的月份條，不引入圖表套件。

## 金額與月份

依使用者 2026-09-24 確認，日期使用台灣日曆日期：

| 目前狀態 | 金額 | 歸屬日期 |
| --- | --- | --- |
| 已交稿 | 全額為真實收益，沒有日期也認列 | 有實際交稿日才歸入月份；缺日期列為未分月份 |
| 未交稿且已收訂金 | 已收訂金為暫時收益 | 訂金收款日 |
| 未交稿 | 訂單金額減已收訂金，為未完成收益 | 預計交稿日 |

每月總計與年度總計均為三類相加，包含未完成金額，不能當成已收現金。訂金全額預付時不再產生未完成餘額；零元訂單仍視為已設定金額。計算使用整數分，回應內的 `cents`、各類與 `total` 皆為整數分；顯示時才轉成元。

依使用者同日後續修正，**已交稿狀態決定真實收益，日期只決定月份與年度**。報表上方「累計真實收益（所有年度）」加總所有已交稿且已設定金額的訂單，包含未填交稿日、封存及零元訂單；「其中未填交稿日」是已認列金額的子集，不再額外加總。切換年度不改變累計真實收益；年度表格只呈現能確認歸屬日期的金額，不將無日期的歷史收入塞入當年。補填日期只調整月份歸屬，不再次認列收入。

報表為**目前狀態快照**。例如 1 月收 300 元訂金、預計 3 月完成的 1,000 元訂單，先在 1 月列暫時收益 300 元、3 月列未完成餘額 700 元。4 月交稿後，改於 4 月列真實收益 1,000 元，原 1 月訂金及 3 月餘額不再計入。跨年也採相同規則；不是凍結的歷史月結、收款流水帳或扣除成本後的淨利。

包含所有類型、封存與擱置訂單，與看板篩選及已交稿是否載入無關；封存只影響展示，不代表取消收入。原始狀態仍為 `cancelled` 的舊單排除。一般工作階段、Trello 標籤及原卡片文字均不能推定收到訂金。

## 日期與待補資料

- 管理編輯視窗新增已收訂金、訂金收款日、預計交稿日與實際交稿日。沒有訂金填 0，訂金不得超過正式金額；清除金額或降低至訂金以下前須一併修正收款紀錄。
- 未交稿改為已交稿時，若未填實際日期，後端記錄當天台灣日期；明確填入的日期優先。一般內容修改不重設交稿日期。退回未交稿時清除實際交稿日，再次交稿重新記錄。
- 舊已交稿訂單若有 `history` 可證明最後一次由非交稿狀態進入交稿，唯讀換算該事件的台灣日期。不使用建立日期、匯入日期、最後修改日或 Trello 最後活動時間代替。
- 不能確認的日期留空。已交稿且已設定金額者仍納入累計真實收益，另列「未分月份的真實收益（已認列）」，不列為待補收入。未交稿的訂金與餘額仍各自判定日期，缺日期者列為待補，完整的一部分仍可計入年度。未報價的訂單另外列出，不用 0 代替未知。
- 待補明細、月份明細及全年明細可直接開啟訂單補填。新報價與日期沿用原本的儲存、還原、未儲存確認與版本衝突處理。

## 資料與 API

`admin.update` 新增選填的頂層 `revenue`：

```json
{
  "depositAmount": 300,
  "depositReceivedOn": "2026-01-31",
  "expectedDeliveryOn": "2026-03-15",
  "deliveredOn": null
}
```

保存在 `detailsJson.revenue`，不增加 Sheets 欄位。日期為 `YYYY-MM-DD` 或 `null`，金額為 0 至訂單總額、最多小數兩位。整個 `revenue` 省略則保留目前值，舊頁及拖曳仍相容；清除訂金需明確送 0 並將收款日設為 null。`details.revenue` 不是寫入入口，新收件忽略私有欄位。舊來源、系統預估、通知及草稿第 4 版不變。

`admin.revenue` 接受 `{ year: 2026 }`，省略年度時使用目前台灣年份。每次驗證管理權限後一次讀取完整 Orders，回傳年度選項、十二個月、全年合計、所選年度明細、所有年度未填日期／金額清單與產生時間。新增 `realized: { cents, entries }` 保存所有年度已認列的真實收益與明細，金額使用整數分；既有 `undated.realized` 與明細保留，屬已認列但未分月份的子集，前端待補清單排除這些已交稿金額。`admin.get` 接受 `{ orderId }`，權限通過後取得最新完整訂單供編輯，避免用報表摘要覆蓋原資料。兩者均為唯讀，不觸發通知。

前端只有開啟報表、切換年度、按更新或在報表中儲存變更才讀取，不輪詢、不保存報表到瀏覽器儲存。年份與明細範圍只留在目前頁面的記憶體。失敗保留上次快照與其年度並標示未更新；登入失效、登出及跨分頁撤銷時清空資料，較晚回傳的舊請求不能復原資料。

## 維護與發布

計算與驗證分別位於 `src/features/orders/revenue.js`、`contract.js`，共用打包至 GAS Core；管理介面由 `revenue-view.js`、`revenue-editor.js` 與 `revenue.css` 負責。後端入口位於 `Orders.gs` 與 `Web.gs`。發布時先部署 GAS，再依既有 GitHub Pages 流程發布前端，不需 Sheets 遷移。

驗證包含 `tests/revenue.test.mjs` 的跨月、跨年、小數、零元、缺值、封存、權限、歷史、拖曳相容與完整訂單快照；執行 `npm test`、`npm run build`、`npm run check`。瀏覽器驗收需覆蓋年度／月份切換、補填日期、超額訂金阻擋、交稿轉換、儲存後重新讀取、更新失敗保留快照、登出清空與手機表格內捲動。只使用虛構資料，啟動規則沿用 `AGENTS.md`。

2026-09-24 的來源合併與主導覽更新分別記於[收益整合驗證](../records/revenue-2026-09-24.md)，後續全專案回歸見[專案整理紀錄](../records/project-review-2026-09-24.md)。各階段測試數量、介面入口與正式發布狀態以該次紀錄為準。
