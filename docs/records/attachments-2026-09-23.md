# 多檔參考附件驗收

## 範圍與決策

依使用者要求，參考檔案最多五個，素材連結改為選填；檔案與連結至少提供一項。每檔上限 10 MiB、合計 45 MiB，為 GAS 相簿請求保留空間；較大素材使用連結。貼圖保留圖片類型限制，角色動畫與小動圖可上傳文件。原單檔草稿改為第 4 版 `references` 陣列；付款、價格、匿名公開進度與 Trello 歷史規則不變。

原問題是選檔只建立本機預覽，後端沒有保存檔案；Telegram 也只傳文字。新增私人 Drive 儲存、分檔上傳與完成後收件、管理員附件讀取、圖片／動畫／文件通知。通知逐位逐檔保存結果；只重試未送達部分。舊版已保存連結的單保持可編輯，過去未上傳的本機圖片無法補回。

## 已完成檢查

- `npm test`：79 項通過；包含五檔／第六檔拒絕、10／45 MiB 邊界、偽裝圖片、雜湊不符、匿名讀取拒絕、偽造附件 ID、上傳配額、Drive／Sheets 寫入後中斷、同識別碼重試、多收件人相簿部分失敗、整組拒絕改傳文件、舊通知部分送達相容及成功回應缺項處理。
- 以真正前端送件處理器連接 Apps Script 測試環境，模擬第二檔上傳成功但回應中斷：重試順序為 0、1、1、2、3、4，只保存五個檔案及一筆訂單。這是測試替身，不等同正式 Google／Telegram。
- `npm run build`、`npm run check` 通過，94 支影片、50 筆表單素材來源與 48 款檢查維持通過；修改過的 JavaScript／Apps Script 執行語法檢查。
- 本機瀏覽器使用虛構資料：後台列出五檔、逐檔取得並解碼 320×200 圖片、建立下載原檔連結；空白素材連結可儲存，儲存後五檔仍存在。桌機 1920×855、手機 390×844 檢視，手機頁寬 390、視窗寬 370，無橫向溢出，主控台無錯誤。
- 表單已確認檔案欄允許多選、最多五檔文字、連結選填標示；兩者皆空時顯示繁中提示，只填 HTTPS 連結可進入確認頁。

## 雲端驗證

既有 GAS 來源與部署設定已備份、核對後更新；Google 新增的 `drive.file` 權限由使用者本人完成授權，`setupReferenceStorage` 已成功執行。2026-09-23 更新既有 Web App 為第 8 版，網址不變；保留第三版連結表單收件／同碼重試相容性。更新前後匯出 Orders 比對：176 筆原資料逐欄未改動，新增一筆虛構附件驗收單，共 177 筆、31 欄。測試單已標示「系統附件驗收」並移至已交稿，保留紀錄。

在 GAS 擁有者執行環境上傳五張虛構 320×200 PNG，逐檔從私人 Drive 取回，大小及雜湊核對成功；首次個別圖片傳送成功後，依使用者後續要求改為相簿。再次使用相同五檔呼叫正式 Telegram API，五項皆成功且 `media_group_id` 相同，確認為一組圖片相簿。沒有新增第二筆測試單，也沒有重送原有訂單通知。臨時驗證入口只允許擁有者執行，並於建立正式部署版本前移除。

Chrome 自動選檔因擴充功能尚未允許存取檔案網址而遭拒，已請使用者開啟；此限制只影響代理測試工具，實際五檔儲存及相簿已由 GAS 驗證。瀏覽器端真實選檔到送件的完整流程、正式後台互動式附件讀取及下載落地尚未宣稱驗收通過；本機後台測試與正式後端測試分開記錄。

設定、資料保留及回復方式見[附件維護](../development/reference-attachments.md)。所有實際訂單備份、執行狀態與驗收素材放在專案外，不公開私人 ID、憑證或角色設定。
