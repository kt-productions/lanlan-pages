# 暱稱與封存驗收

## 行為與資料

2026-09-23 依使用者更新需求，公開進度以委託者暱稱顯示新表單，Trello 沿用原核可名稱。表單暱稱欄與送件提示同步說明名稱會公開；聯絡方式、附件及內部備註仍不公開。

封存是獨立附加狀態，保留七階段、急件、擱置與報價。公開 API 在計數及分頁前排除封存；後台「所有工作」、急件、擱置均排除，僅「封存」篩選顯示，可再套用類型、階段及搜尋。編輯視窗可勾選／解除封存；儲存後若離開目前範圍，關閉視窗並更新看板。

GAS 第 9 版沿用原部署網址，Orders 由 31 欄追加第 32 欄 `isArchived`。升級前後私人備份比對，177 筆原資料的前 31 欄逐欄一致；新欄空白時沿用 Trello 來源封存，故原 4 張封存卡片自動排除。沒有刪除或批次改寫訂單。明確解除封存時保存 false，來源原始封存值保留。舊管理分頁省略新欄時保留原旗標。

## 驗證

- `npm test`：82 項通過，涵蓋封存／還原、舊欄升級不覆寫、Trello 封存相容、公開件數／分頁、舊客戶端保留封存、未知型別拒絕、暱稱投影與其他私人欄位保護。
- JavaScript／GAS 語法、`npm run build`、`npm run check` 通過；影片及素材檢查維持通過。
- Chrome 本機替身資料：72 筆中預設顯示 70 筆，封存篩選顯示 2 筆；一般測試單封存後從一般看板消失，封存篩選可找到；解除後回到原階段，急件／擱置保留。此 UI 測試未連正式 Telegram。
- 桌機 1920×911、手機 390×844 檢視；手機封存篩選與編輯視窗可操作，視窗寬 370px，無整頁橫向溢出。兩個驗收分頁主控台沒有錯誤或警告。
- 在正式 GAS 擁有者環境用既有虛構附件測試單封存並還原：公開數量 173 → 172 → 173，測試單封存時消失、解除後恢復暱稱；原階段與通知紀錄不變。只新增此測試單的兩筆修改歷史，未新增委託或傳送通知；臨時擁有者驗證入口完成後移除。

本機瀏覽器互動與正式後端寫入分開驗證；正式 Telegram 登入後的互動尚未在本次重做。升級備份、驗證來源及真實資料只保存在專案外。不得因封存而刪除附件、通知紀錄或歷史；資料契約見[服務 API](../reference/order-api.md)。
