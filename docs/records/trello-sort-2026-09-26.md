# 歷史已交稿排序補正

日期：2026-09-26。依使用者提供的新網站與舊系統對照，延續已授權的排序修正與發布工作。

## 原因與修正

前一版僅按本站 `updatedAt` 排序，漏掉 Trello 同批匯入的 `updatedAt` 都是匯入時間，歷史委託因此落到編號排序。新完成委託已有不同的本站更新時間，所以能排在前方。

`contract.js` 改在讀取時計算 `sortUpdatedAt`：本站時間仍等於匯入時間且來源最後活動有效時，使用 `source.lastActivity`；後續在本站更新的委託仍採 `updatedAt`。公開及管理 API 提供同一欄位，分頁與前端補載共用排序；前端也可讀取舊版公開投影既有的來源時間。原本的 `updatedAt`、來源、修改歷史與收益日期均不改寫。

## 驗證

- 專案外的原始匯入資料中，47 筆歷史已交稿小動圖按修正後規則排列，逐筆與原看板 `cardPosition` 順序一致；公開投影與管理資料的排序一致。原始資料及真實名稱沒有加入測試或公開文件。
- 新增虛構的同批匯入 35 筆案例，涵蓋公開／管理跨頁補載、同匯入時間、未公開來源名稱、後續本站更新置頂、原始列不變，以及舊回應及無效來源時間相容。
- 177 項離線測試全部通過；修改檔案語法檢查、正式網址建置、`npm run check` 與差異檢查通過。
- 部署前備份 GAS 第 24 版，核對雲端未發布來源與正式版一致；本次後端只有 `Core.gs` 不同，manifest 與其他來源不變。

## 發布與界線

沿用既有 GAS deployment 與 main 驗證、production 快轉發布流程，先更新向後相容的 GAS 再發布前端。正式發布結果以 [Pages Actions](https://github.com/kt-productions/lanlan-pages/actions/workflows/pages.yml) 與 `release.json` 核對，完成後使用正式進度頁與使用者附圖比較。

本次不重新匯入、不改寫訂單、不發送通知，沒有持續同步舊系統。原始資料比對及離線測試不能代替正式頁面的最終驗收。
