# 管理登入自動完成驗收

日期：2026-09-23。依使用者要求，移除一般登入流程中必須在 GAS 回程頁手動點連結的步驟。

## 行為與原因

Google Html Service 的 iframe 只允許使用者操作觸發頂層導覽，不能直接使用自動 `top.location` 完成回程，見 [Google 官方限制](https://developers.google.com/apps-script/guides/html/restrictions)。管理頁改為同步開啟 Telegram 驗證視窗；原頁取得經驗證且綁定 browserKey 的票證後交換登入，自動載入未交稿看板。驗證視窗嘗試自動關閉，關閉被瀏覽器拒絕不影響原頁登入。

等待可取消，拒絕、逾時及連續網路錯誤會恢復可登入狀態；交換中斷保留既有重試。阻擋彈出視窗時沿用原分頁登入及手動回程。既有白名單、PKCE、RS256、nonce、單次 state、票證與工作階段期限不變，沒有增加 Telegram 或 Google 權限。

## 本機驗證

- `npm test`：102 項通過，新增原瀏覽器綁定、拒絕、取消、逾時、舊 state、不合法目的地、視窗受阻、網路重試及關閉失敗案例。
- 變更的 JavaScript 語法檢查、`npm run build`、`npm run check` 通過。
- Chrome 桌機 1905 × 904：使用隔離的虛構 OAuth 與本機後端，實際開啟視窗、確認、原頁自動交換票證及載入看板、驗證視窗關閉、登出與取消後重試通過；主控台無錯誤。
- 手機 390 × 844（內容寬 375）：登入文字與操作無橫向溢出，開窗等待與取消正常，主控台無錯誤。模擬拒絕視窗的瀏覽器控制逾時，未列為手機實測通過；拒絕行為由測試驗證。
- 本機僅替換 OAuth 目的地和 API 傳輸，登入協調、後端驗證及管理頁沿用專案來源；不能代替正式 Telegram 與 GAS iframe 驗收。

## 發布狀態

GAS 已更新至第 12 版，沿用原 Web App 網址，只更新 Auth 與 Web。前端已經 GitHub Actions 建置與發布成功，正式頁可開啟 Telegram 驗證並持續等待結果，主控台無錯誤。瀏覽器工具無法操作獨立驗證視窗，因此以一般分頁開啟同一份尚未使用的 Telegram 授權網址接續驗收；使用者確認 Telegram 後，原管理頁自動交換票證並載入 43 件未交稿，正常顯示 39 件未封存工作；全程沒有點 GAS 返回連結。正式管理頁沒有錯誤，已交稿仍需手動載入。這次驗證視窗未自行關閉，登入功能不受影響；驗收後已關閉驗證頁並保留管理看板。未修改正式委託或發送收件通知。
